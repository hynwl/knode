# AgentCanvas — 랜딩페이지 디자인 브리프

랜딩페이지 아티팩트를 만들 때 참고할 디자인 철학 + 서비스 정보 요약.
색/타이포/간격 등 하드 토큰은 `design/tokens.ts` 가 SSoT다 — 여기 적힌 값은 그 파일에서
그대로 가져온 것이고, 랜딩페이지는 앱과 "같은 제품처럼 보이는" 브랜드 확장이어야 한다
(완전히 다른 마케팅 사이트 톤으로 이탈하지 않는다).

---

## 1. 이 프로덕트가 뭔가 (서비스 요약)

**한 줄:** CrewAI 멀티 에이전트 팀을 캔버스에 노드로 연결하고, 실제로 실행해서 그 결과가
그래프 위에서 움직이는 걸 보는 툴.

**존재 이유:** CrewAI는 좋은 프레임워크지만 Python이라, 실험 한 번마다 "파일 고치기 →
터미널에서 재실행 → 로그 스크롤 → 어느 에이전트가 멈췄는지 추측 → 다시 고치기" 루프를
반복해야 한다. 팀 구조는 코드 속에만 존재하고 눈에 보이지 않는다. AgentCanvas는 그 팀을
보고, 바꾸고, 도는 걸 지켜볼 수 있는 대상으로 만든다.

**핵심 원칙 — 아무것도 가짜가 아니다.** 캔버스의 그래프는 백엔드에서 실제
`crewai.Crew`로 컴파일되어 실행된다. 화면에서 움직이는 건 진짜 실행이 SSE로 흘러들어오는
것이지, 연출된 애니메이션이 아니다. 그리고 언제든 **Export to Python**으로 순수 CrewAI
`crew.py`로 빠져나갈 수 있다 — 이 툴에 갇히지 않는다는 게 제품의 핵심 약속.

**차별점 (Before/After 표, README에서 그대로 가져온 톤):**

| | Python으로 직접 짤 때 | 캔버스에서 |
|---|---|---|
| 프롬프트 하나 고치기 | 파일 편집 → 재실행 → 스크롤 | 노드 클릭, 타이핑, 실행 |
| 뭐가 일어나는지 보기 | 터미널 스크롤백 | 노드가 빛나고, 와이어가 펄스치고, 생각/툴콜이 콘솔에 흐름 |
| 남이 짠 크루 이해하기 | 스크립트 전체 읽기 | 파일 열고 보기만 하면 됨 |
| 넘겨주기 | "이 레포 실행해봐" | `.acanvas.json` 하나, 또는 링크 |
| 빠져나가기 | — | Python으로 export. 그냥 CrewAI. |

**주요 기능 (랜딩 섹션 후보):**
- **노드로 조립** — 14종 노드(LLM/Agent/Task/Tool/Crew/Input/Output/Knowledge/Memory/Human
  Input/Router/Guardrail/Note/Group), 타입 소켓이 잘못된 연결을 물리적으로 막음, 순환
  참조 거부, 필수 연결 누락은 토큰 쓰기 전에 상태바에서 걸림.
- **실행이 그래프 위에서 보임** — 노드 상태 링, 실행 순서대로 와이어를 타고 흐르는
  파티클, 콘솔에 실시간 생각/툴콜, 헤더에 경과시간·토큰 비용.
- **실패도 그래프 위에서 보임** — 실패한 노드 자체가 에러를 입는다. 로그 214번째 줄이
  아니라.
- **BYOK, 키는 서버에 안 남음** — 브라우저 세션 메모리 기본, 로그 마스킹, export 시
  시크릿 스캐너, 그래프 파일엔 키 슬롯 "이름"만 저장.
- **로컬 무료 실행** — Ollama 자동 감지, 키 없이 도는 템플릿 표시, $0/계정 없음.
- **Dry Run** — LLM 호출 없이 실행 순서와 예상 비용만 리포트.
- **중간 정지/개입** — Stop으로 즉시 취소, 특정 Task를 "완료 시 사람 리뷰"로 표시하면
  실행이 멈추고 브라우저에서 피드백을 받은 뒤 이어감.
- **Export to Python** — `crew.py` + `requirements.txt` + `.env.example`. 이 앱을
  import하지 않는다.
- **템플릿** — Hello Crew, Blog & SEO Crew, Market Research Report, YouTube Script
  Pipeline, Local-only Summarizer($0).

**신뢰 신호:** 오픈소스(AGPL-3.0), 테스트 1,300+ (백엔드 828 / 프론트 513 / E2E 36), 대비율·
키보드 경로·reduced-motion까지 테스트로 고정, 가입 없음, Docker 한 줄 실행.

## 2. 디자인 철학

### 2.1 근본 태도 — "제품 자체가 증거"

이 랜딩페이지는 **앱 스크린샷을 부끄러워하지 않는 제품**을 소개하는 페이지다. 오프닝
화면(`Welcome.tsx`)이 이미 그 원칙을 증명한다: 중앙 정렬 히어로 대신 **비대칭 스플릿**
(왼쪽 로고+헤드라인+CTA, 오른쪽에 진짜 편집 화면 스크린샷)을 쓴 이유는 "가운데 정렬
히어로는 어느 제품에나 붙는 기본값이라 이 제품이 뭔지 한 장으로 보여주지 못하기"
때문이었다. 그린 가짜 UI가 아니라 실제 앱을 찍은 스크린샷을 쓰고, 그 뒤 배경도 캔버스가
실제로 쓰는 도트 그리드(`bg-dot-grid`)를 그대로 재사용한다.

랜딩페이지도 같은 태도를 이어받아야 한다: **연출보다 증거.** 목업이 아니라 실제 캔버스/
노드/콘솔 스크린샷, 실제 익스포트된 코드, 실제 로그 라인.

### 2.2 비주얼 아이덴티티 — "다크 노드 에디터"

- **배경은 짙은 네이비-블랙** `#0b1220`, 표면은 그 위로 단계적으로 밝아지는 3단계
  surface (`#141d30` 기본 → `#0e1626` 함몰(입력창/콘솔) → `#1a253c` 융기(버튼/드롭다운)).
  완전한 블랙이 아니라 살짝 블루 틴트가 들어간 다크.
- **도트 그리드 배경** (`#1e2b42`, 26px 간격, 1.4px 반지름) — 캔버스라는 정체성을 배경
  텍스처만으로도 즉시 전달한다. 랜딩에서도 빈 공간을 채울 때 이 그리드를 재사용하면
  "같은 제품"이라는 신호가 강해진다.
- **노드 헤더 그라디언트 4색이 곧 브랜드 팔레트**: `agent`(인디고 `#4f46e5→#4338ca`),
  `task`(에메랄드 `#059669→#047857`), `tool`(앰버 `#d97706→#b45309`), `llm`(로즈
  `#e11d48→#be123c`). 이 네 가지가 앱 전체에서 "이건 에이전트다/태스크다/툴이다/모델이다"
  를 색으로만 구분하는 언어다. 랜딩페이지에서 4개 기능을 나란히 보여줄 때 이 4색을
  그대로 쓰면 자연스럽게 브랜드 언어가 확장된다.
- **실행 강조색은 시안→인디고 그라디언트** (`#22d3ee → #6366f1`, `run-btn`). "지금 도는
  중"이라는 감각을 상징하는 유일한 색 조합이므로 CTA 버튼에 이걸 쓰는 게 가장 자연스럽다.
- **모노스페이스는 장식이 아니라 정보 밀도의 신호**: 노드 헤더 마크, 소켓 라벨, 콘솔,
  코드 박스, 배지, 원가/토큰 카운터 전부 `IBM Plex Mono`. "이 화면은 로그/데이터를 보여준다"
  는 걸 폰트만으로 구분한다. 랜딩에서 코드/비용/수치를 보여줄 땐 모노를 쓴다.
- **디스플레이 폰트는 `Sora`** (헤드라인/워드마크), **본문 UI는 `Manrope`**. 워드마크
  "Agent"+"Canvas" 두 파트는 살짝 다른 굵기/스케일 비율(1.3배)로 조합돼 있다 — 완전히
  균일한 워드마크가 아니라 리듬을 준 조합.
- **모서리는 각지지 않지만 둥글지도 않다** — radius가 3px(스와치)부터 13px(모달)까지
  세분화되어 있고 기본은 9~10px. "소프트웨어스러운 각짐"과 "장난감 같은 둥글함" 사이.
- **그림자는 항상 짙고 확산됨** (`0 6px 20px -8px #00000090` 등) — 떠 있는 느낌보다
  "짙은 배경에서 살짝 들뜬" 느낌. 밝은 배경용 얕은 그림자 문법을 쓰지 않는다.
- **접근성은 타협 대상이 아니다** — 원본 아티팩트 색이 WCAG 4.5:1 대비를 못 넘긴 유일한
  케이스(`textFaint`)를 명도만 조정해서 통과시켰고, 이걸 테스트로 고정해뒀다
  (`contrast.test.ts`). 랜딩에서도 본문 텍스트 대비는 반드시 통과해야 한다 — "다크 테마니까
  흐릿해도 된다"는 안 된다.

### 2.3 카피 톤 — "기능 나열이 아니라 대조로 증명"

- 문장은 짧고 구체적이다. 형용사 대신 **행동과 숫자**로 증명한다. ("빠릅니다"가 아니라
  "노드 클릭, 타이핑, 실행" / "안전합니다"가 아니라 "키는 브라우저 세션 메모리에만,
  서버엔 절대 안 남음").
- **Before/After 대조 표**를 자주 쓴다 — "Python으로 직접 짤 때 vs 캔버스에서" 같은 구조가
  README와 오프닝 화면 전반에 반복되는 패턴이다.
- 헤드라인 예시(실제 오프닝 화면 카피):
  - EN: *"Wire up an agent team. Watch it actually run."*
  - KO: *"에이전트 팀을 연결하고, 실제로 실행하세요."*
  - 부제: *"Drag CrewAI nodes onto the canvas, connect them, hit Run. Bring your own API
    key, or go free on Ollama."*
- 3가지 핵심 포인트는 항상 **가입 없음 / $0로 실행 가능 / 결국 그냥 코드(락인 없음)**
  순서로 제시된다 — 이 셋이 신뢰를 얻는 핵심 논거다.
- 자기 자랑보다 **정직한 한계 명시**를 선호한다 (예: "편집기는 노트북/데스크톱 화면에
  맞춰 만들어졌습니다" — 모바일에서 억지로 되는 척하지 않음). 랜딩에서도 과장 대신
  "이건 되고, 이건 아직 이렇다"를 솔직히 쓰는 편이 이 브랜드 톤에 맞다.
- 한국어/영어 완전 이중 지원이 정체성의 일부 — 랜딩도 두 언어를 대칭적으로 고려해서
  카피를 짜는 게 좋다 (`break-keep`으로 한글 어절 중간 줄바꿈 방지 등 디테일 포함).

### 2.4 레이아웃 원칙

- **비대칭 2단 그리드** (`0.92fr` : `1.08fr` 비율) — 왼쪽 텍스트/CTA, 오른쪽 시각 증거.
  완전히 5:5로 나누지 않는다.
- 애니메이션은 **`animate-rise` + 순차 지연**(120ms → 200ms → 280ms → 340ms →
  400ms) 으로 요소가 아래에서 살짝 떠오르며 순서대로 등장 — 화려한 모션이 아니라
  "읽는 순서"를 만들어주는 절제된 스태거링.
- 자동 포커스나 강제 스크롤을 쓰지 않는다 — 배려는 하되 사용자를 밀어붙이지 않는 태도
  (Enter 키를 일부러 안 듣고 Esc만 받는 것도 같은 이유: 전역 키 가로채기가 다른 상호작용을
  깨는 걸 피함).
- CTA는 하나만, 명확하게: *"Open the canvas" / "캔버스 열기"*.
